# Zodo：DSH 日程插件开发路线

本分支从 `42075df` 开始独立迭代。目标不是复制一套通用生产力平台，而是让 DSH 用户每天打开 Zodo，就能回答三个问题：接下来要做什么、今天还有多少可安排时间、变化以后怎么调整不伤及既有承诺。DSH 是唯一正式 UI，Rust Core 仍是唯一事实与审批来源。

## 产品取舍

- 首屏给出下一项、今日已定日程和待安排任务。不要求先选模型、建项目或连日历。先把人工操作做顺，再加 AI 提议。
- 手动固定预约、日历导入忙碌和可移动任务分配明确区分。看不到数据、数据过期和没有事件不能都叫「空闲」。
- 计划先展示拟移动内容与原因，写入沿用 Core 的 revision / explicit approval / receipt；不移动已经开始、过去或锁定的事项，不为凑满日程制造建议。
- 默认本地使用。外部忙碌字段最小化；不把私人标题送进模型，无授权不联网、发提醒或写第三方日历。不为 v1 增加第二套 UI 或日历双向同步。

## 迭代顺序

1. **可信日程**：可前后浏览和回到今天；同一时间轴按本地显示日期与实际时间排序，跨午夜和 DST 不误归类。添加可区分、不泄露标题的导入忙碌提示；导入缺失/过期时不误导。先验证现有预约、容量、任务编辑入口无回归。
2. **快速安排**：用日期和最少字段直接添加预约/安排任务；保存后能找回它，取消、冲突、重复点击和失败明确可恢复。Core 继续负责业务写入。
3. **可解释重排**：只在用户确认后应用；把会变、不变、放不进去的项目分开。验证陈旧版本、审批撤销和锁定预约。
4. **交付与复核**：轻量初次使用、可访问键盘路径、适配窄窗口、空/错/加载状态、隔离安装/升级/卸载。写清能验证到哪一层，不把 fixture 或 stub 称为真实 Host 验收。

## 完成标准

- 人面对合成的一周，能不启用 AI 完成「录入 → 看日程 → 调整 → 处理冲突」；不用理解 Core 概念，也不丢预约/已确认事实。
- 使用已导入和没有导入两种合成数据，覆盖时区、日期边界、过期状态、失败和取消。核心与适配器的自动回归通过。
- 用隔离 DSH profile 复核插件入口、交互和生命周期；如果真实 Host 缺失或不能安全运行，报告具体未验证门槛，不虚报完工。所有变更只提交到 `xiaoz/zodo-scheduler`，不合并、不发布、不动真实数据。

## 进度（实现与验收分开）

| 范围 | 分支实现及已验证证据 | 仍需验证 |
| --- | --- | --- |
| 可信日程 | 日期导航、本机时间轴、午夜和 DST、脱敏忙碌与新鲜度进入适配器；合成回归覆盖纯逻辑和只读行为。 | Windows Chrome 夹具已验证渲染和窄窗导航；隔离 DSH Desktop 中仍需检查有／无忙碌覆盖和过期状态。 |
| 快速安排 | 固定预约、任务日期、安排具体时段分开；候选按工作空间日期筛选；指定时段必须用 Core 严格提案。真实 HTTP 合成冒烟已确认预览和批准不新增分配，提交只新增一条。 | Chrome 夹具已验证录入、取消与丢失回执后的刷新；仍需在真实 DSH Desktop 复测。 |
| 可解释重排 | 默认只追加；明确选重排才允许移动未来未锁定安排。Core 回归验证审批绑定的删除集合和候选开始时间漂移会拒绝提交。 | 隔离 Host 中用同一组固定承诺对照验证两种模式。 |
| 交付与复核 | Windows x64 分支包及校验通过；同次构建的隔离 Chrome 回归 32/32，含 390px、键盘及丢失回执。 | 独立 DSH Desktop profile 下的加载、重启、升级、卸载和数据隔离。 |

分支尚未通过最终验收。命令、精确版本和已知环境限制见[宿主验收门槛](SCHEDULER_HOST_ACCEPTANCE.md)。
