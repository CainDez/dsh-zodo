# Zodo AI：两种使用模式

## 日常设置

“模型”和“隐私”导航使用同一个“模型与隐私”设置页。工作区只有两个合法模式：

- **仅本地**（`local_only`）：所有 Core AI 请求只使用本机模型；本地不可用就停止，绝不转云端。
- **允许云端辅助**（`cloud_assisted`）：获准的普通上下文可使用选定云端；禁止外发的数据只在本地处理。云端缺少凭据、未配置、禁用或未授权时，在发送请求前选择本地；本地也不可用就明确报错。开始网络请求后的失败不自动跨提供方重试。

首次保存云端辅助需要确认外发范围，将已保存云端连接的具体 ID 写入允许名单。空名单和通配符不授权云端。切换模式不会修改笔记或附件自身的数据等级，也不会改变 DSH 对话模型。

## 内容与授权边界

目标拆解只构造目标标题、成功标准、截止日期、关联项目名称/范围和可选计划视界；收集澄清只使用用户主动提交的原始收集文本。不自动附加笔记正文或附件。标题、范围和收集文本不是自动脱敏，请勿将禁止外发内容复制到这些字段。

网关收到明确的 `DeviceOnly` 敏感度时，无论模式、云端凭据或角色偏好如何都不会选择云端。Host 结构化导出检查、受限历史派发拦截与人工业务批准是独立的安全边界，不能被模式切换绕过。

## 实际状态与高级设置

页面显示 Core 根据当前配置返回的普通请求、禁止外发内容、目标拆解与收集澄清的实际路由和原因。配置、权限及凭据预检通过**不等于**服务可达或推理成功。

模式与连接分别保存：工作区策略和模型配置不伪装成一次原子写入。连接有草稿时先保存连接，再确认云端授权。刷新会同步干净草稿；已修改草稿遇服务器变化会保留并阻止覆盖，用户可放弃草稿重新载入。保存前的基线核对不是原子 CAS。

默认折叠端点、凭据变量名、连接启用状态、角色路由、宿主模型目录、诊断与授权信息。固定本地角色不转云端；优先云端角色仍受模式和内容保护限制。宿主模型目录只读，填入只改草稿，不复制密钥、不修改 DSH 设置。

密钥由 Core 启动环境提供，界面只显示存在状态。原文诊断不是历史清除开关；运行记录、备份和导出仍按敏感资料处理。

本地端点只能是本机回环地址；HTTP 客户端不跟随重定向、不自动使用环境代理。本机服务自身是否再代理到远端，需要在该服务中约束。

## 开发阶段约定

只维护当前结构与接口，不保留旧模式、旧全局资料等级、字段别名或隐式命令版本。旧策略、未知字段和缺失的命令版本明确拒绝；笔记/附件的内容分级不是过期字段，必须保留。

不在正常运行路径执行升级迁移或旧版自动转换。开发实例若残留过期设置，先备份，再进行明确的一次性设置重置；不删除任务、目标、笔记或历史回执。

## 安装更新

构建与源码修改不会自动替换运行中的 Core。更新时先做一致性备份，确认没有需要继续的 AI 运行；停止共享 Core 后替换 [发布版程序](<../target/release/zodo.exe>)，不启动同一数据目录的第二个 writer。

源目录链接安装无需重新复制源码，但客户端资源需要重新构建。没有开发 watcher 的桌面 Host 不会因为修改源码就自动更新；须刷新并实测当前 GUI，不能用另起服务器冒充当前应用。必要时由用户重启 DSH。

## 验证

Rust 测试验证两模式、内容分级、显式提供方、凭据预检、安全回退、严格字段与审批权限；隔离浏览器验证保存、授权、状态、错误、草稿冲突和高级折叠。历史格式的拒绝测试不代表保留兼容。合成服务通过不代表真实云端推理成功。
