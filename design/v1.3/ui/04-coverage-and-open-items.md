## 首期必须补齐的技术和 UI 证据

1. 锁定 Harness 版本，验证插件装载/卸载、可用 Slots、宿主详情/批准载体、内部五入口、局部样式与快捷键冲突处理，不夺取 root/全局导航。
2. React → Client model/注入 service → Host RPC bridge → Rust Core 的真实纵切；Cordis 只管生命周期和接线，Core 保有事实、授权、时间、依赖和提交。
3. 人工 UI face 与 agent tool face 独立授权、输出裁剪和批准。工具结果可能写会话日志并在后续换模型时重用；device_only 不能仅因当前本地路由而导出到 agent 历史。
4. 中文 IME、持续编辑、取消、stale、冲突、未知提交、receipt 与 effects 全状态；宿主关闭/插件热重载后按 Core 回执和快照恢复，宿主事件回放不重写业务。
5. 宿主/网络/Core 分别掉线、授权撤销、model 改路由、会话切换、插件多实例及 Core 重启的实证。UI 关闭不删除 Core 持久事实；Core 也停止时不承诺推理/通知持续执行。

## 保留的未决项与完成门槛

具体 Slot/tab 注册、RPC 类型生成、宿主信任标识与人工批准通道要做 PoC 后锁定，不能靠文档猜测 API。接口样例不是全量 schema；tokens 不证明宿主兼容、字体/缩放或可达性通过。后续 Flutter 的 FFI、工具链、Apple 签名和移动通知继续单独验证。

完成状态至少分文字、旧参考、Harness 已绘制、可交互、真实 Core、宿主/平台验证。全 30 屏、16 弹层、8 流程继续逐项验收；静态参考、导航文字或“插件启用”不能关闭尚未验证项。无需重新选择清晰日程，但需要把其信息层级适配宿主。
