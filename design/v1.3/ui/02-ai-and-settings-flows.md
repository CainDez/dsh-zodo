# 02 · AI、隐私与设置流程规格

版本 1.3 · 状态：Harness 首期插件设计提案，2026-10-24，Asia/Shanghai。Rust 独立 Core 与全功能目标不变，Flutter 独立客户端后续实施。页面/抽屉/弹层和业务语义继续共用；七张 D01–D06/M01 PNG 未改变，只作旧独立客户端视觉参考，不是 Harness 新截图，插件视觉、交互和真实能力尚未实现。

## 0. 首期载体、两种权限面与日志边界

首期为 Harness 内 React + Slots 的 Zodo 工作台、详情及批准视图，Host RPC bridge 调用 Core。五业务入口在插件内部组织，设置为 Zodo 局部设置，不改宿主全局导航、主题、会话模型或审批策略。下文“页面/抽屉”均映射到宿主支持的容器；标明手机/原生的行为仅属于后续 Flutter，不代表 Harness 网页可访问原生后台、系统通知或本地数据库。

人工 UI face 与 agent tool face 分开认证/授权/输出裁剪。人工看到完整详情，不意味着应把同样正文、摘要或标题返回给模型；工具结果可能进入 Harness 会话日志，之后换模型、导出或回放时仍可被使用。device_only 不能仅因当前 agent 是本地模型就外发到会话；若不能约束完整接收/保留路径，返回安全拒绝或经策略允许的最小回执，不能先传正文再警告。需要私密材料的本地理解可由受限 Core gateway 完成，不自动复制到宿主 prompt。

下文批准均指具体 Core 变更的有效批准。Host 的工具允许一次只是一道门控，不等价于 Core grant；可信人工回调绑定主体、提案 hash、数据/策略版本和影响。批准凭据不交给 agent。React/Cordis 不存第二份权威事实，不用宿主历史事件重建后自动执行保存；关闭/热重载后的恢复见第 11 节。

## 1. 共用布局与文案原则

首期设置在 Zodo 插件内采用“局部设置分类 / 主内容”，首屏给当前选择与作用范围，不另造宿主全局侧栏。多步导入/恢复/首次设置使用完整详情面，短确认只处理一个决定。原 440–560 逻辑像素抽屉是旧参考，首期按 Slot 实际宽度重排；窄容器用可返回详情，保留输入/滚动。后续 Flutter 才用独立手机整页。

| 载体 | 使用范围 | 退出规则 |
| --- | --- | --- |
| 主要页面 | 首次设置、模型与处理方式、数据与隐私、外部助理、活动记录、数据与备份、导入/恢复向导 | 有标题、当前位置和返回；保留已填写但未保存内容 |
| 详情抽屉 | AI 澄清、计划预览、数据流向、本次授权、连接详情、导出选项 | 桌面可看原内容；窄屏整页；有明确关闭入口 |
| 短弹层 | 撤销授权、放弃草稿、替换恢复的最后确认 | 显示对象和影响；主按钮用具体动作，不写“确定” |
| 行内状态 | 下载、检查、失败、过期、未保存、提醒待设置 | 靠近相关内容；不只靠 toast 或颜色 |
| 通知条 | 已保存、已停止、导出完成等反馈 | 有后续入口；不能作为唯一持久状态记录 |

主产品使用“Core 所在位置处理”“云端处理”“当前助理”“待你确认”“尚未保存”“重新检查”“数据流向”；只有确认 Core 与浏览器当前设备一致才简写“此设备处理”。技术标识留在连接详情，模型名称/地址留在设置。宿主模型与 Core 模型是不同配置，不能只显示一个“本地”盾牌混用。

避免“AI 已完全理解”“最佳安排”“100% 安全”“智能自动接管”。用“这里有一份建议”“还缺一个信息”“有两项未能安排”。不显示未经定义的可靠度百分比，不使用 confidence 决定授权、替代澄清或把估时当确定事实。

生成时输入仍可编辑；中文输入法组词期间不触发自动预览，结束后更新最新内容。预览不抢焦点、逐字播报或挤掉键盘；旧结果不能覆盖新输入。明确区分“收集内容已保存”与“建议尚未应用”。

## 3. 首次设置：三步页面，可稍后完成

### O01 欢迎页：从 Harness 中的 Zodo 开始

在宿主支持的 Zodo 工作台/详情容器显示标题、说明、空白/演示选择与主动作，不占用 root。后续 Flutter 可映射为独立欢迎页/手机整页。

- 标题：“把想做的事，变成可以推进的安排”。
- 说明：“先收集和整理，再决定是否使用 AI。你可以随时调整。”
- 主按钮：“开始设置”；次按钮：“先体验演示”。
- 下方文字：“无需先连接外部助理。演示内容不会写入你的个人事项。”
- 进入演示时，全局保留“演示数据”标记与“离开演示”，不在个人工作空间偷偷混入样例。

不要求先注册新云账号、下载模型或给 provider key 才能管理事务；但须认证人工 UI 与 Core 连接。首期显示 Host/Core 及浏览器的位置，不能因宿主桌面壳就宣称资料保存在当前设备，也不因 agent 已连接而自动授予其读取权。

### O02 时间与工作习惯

顶部“第 1 步，共 3 步”，字段顺序为：

| 区块 | 默认展示与文案 |
| --- | --- |
| 时区 | “上海时间 · UTC+8”，可搜索地区；说明“日期和提醒按此时区解释” |
| 可安排时间 | “工作日 09:00–12:00、14:00–18:00”，每段可改；这是可编辑默认，不声称用户已确认 |
| 周末 | “每次安排前询问”；另有“默认不安排”“也可安排” |
| 每日投入 | “先不限制”，可设置目标专属上限；不强迫填写不真实的产能 |
| 既有安排 | “稍后连接日历”，允许跳过；不宣称已读取系统日历 |

底部“继续”与“跳过，稍后设置”。选择一套默认规则时，继续页明确显示摘要，不能把尚未点击保存的默认当成用户事实。

### O03 AI 处理方式

标题“你的内容在哪里处理？”，两种单选方案：

1. **在 Core 所在设备处理**：先显示实际设备/可信边界；说明“准备 Core 本地模型后使用，不自动转云端”。子状态“尚未准备”，按钮“准备模型”，次动作“稍后准备”。Core 不在当前设备时，device_only 内容不可送去，即使对方也用本地模型。
2. **连接云端服务**：说明“仅发送你允许的内容。每次可以查看将发送什么”。按钮“添加连接”；先进入设置表单，不代表同意上传所有资料。

底部始终提供“暂不启用 AI，继续使用”，不预勾云回退、笔记上传或 agent 读取。另列“交给 Harness 当前助理”，说明工具结果可进入日志并被后续模型重用；未获独立导出授权不启用。此处只选择处理路径，不修改宿主全局模型/凭据或放宽 Core 数据分级。

本地准备抽屉分“下载中 / 正在检查文件 / 正在测试运行 / 可以使用”。下载大小和进度来自真实状态，不在设计稿捏造具体硬件性能；暂停、重试、空间不足都保留页面。文件下载完成但启动测试失败时写“文件已准备，暂时无法运行”，提供“查看原因”“稍后处理”。

### O04 完成页

顶部“已经可以开始”，摘要显示时区、周末规则、Core/Host 位置及路径。示例“上海时间 / 周末安排前询问 / Core 本地模型尚未准备，手动可用”；主动作“进入今天”，次动作“导入已有事项”。不用“AI 已就绪”冒充实际测试，也不自动把人工内容加入宿主会话。

## 4. 设置主页面与模型连接

### SET01 设置首页（主要页面）

Zodo 局部设置分类保持“时间与提醒 / 模型与处理方式 / 数据与隐私 / 外部助理 / 数据与备份 / 显示与辅助功能”。摘要显示 Core/Host 位置、外部连接和最近备份；宿主拥有的主题/快捷键只给正式设置入口，不在插件复制。未配置写“尚未连接/尚无备份”。

### SET02 模型与处理方式（主要页面；D06 的代表画面之一）

上方标题、当前处理方式摘要；中部左右对比或窄屏上下排列：

- **此设备**：准备状态、实际可用能力、上次测试结果；动作“测试运行”“更换模型”“移除文件”。
- **云端连接**：连接名“我的云端连接”、服务提供方、状态、允许的数据范围；动作“管理连接”“测试连接”。
- **使用规则**：默认“只在此设备处理”；另可选“特定内容允许云端，其他内容留在此设备”。规则须显示具体范围，不能只写“自动选择最佳模型”。

“添加 Core 连接”在详情输入名称、服务类型、必要地址/凭据/模型与测试；密钥遮掩、错误不回显，由安全存储持有。保存不等于发送资料，测试只发无个人内容请求。Harness 当前 agent 的模型/凭据由宿主管理，插件不复制秘密、不偷偷改全局 provider；显示实际路由与可用性，测试成功也不授予正文导出。

保存后摘要：“已保存连接。尚未允许发送个人事项。”更换服务或可读范围时重新检查已有待审建议；不把前一家服务的同意复用给新服务。

### SET03 模型移除与不可用

“移除本地模型文件”用短确认弹层，列出模型名称与占用空间，主按钮“移除文件”。说明“任务和日程会保留，仍可手动管理”。云端连接删除弹层显示“删除连接后，需要重新填写凭据才能使用”，不影响已经保存的任务。

行内不可用文案：“此设备暂时无法生成建议。输入内容已保留。”动作“重新测试”“手动编辑”；只有已有云连接且用户主动选择时才出现“改用云端”，并先展示本次数据流向。

## 5. 数据与隐私：规则与本次发送分开

### PRIV01 数据与隐私（主要页面）

顶部显示真实 Core/Host/浏览器位置，仅同设备时写“个人事项保存在此设备”。说明“Core 本地处理不自动转云；交给宿主 agent 的结果另受日志/后续模型策略约束”。页面分三组，分别标人工查看和 agent 可读范围，不以一组勾选混授权：

- **处理范围**：任务标题与时间、目标与成功标准、笔记正文、附件；每项有“此设备 / 可按次发送 / 明确允许的服务”范围。
- **外部读取**：已授权的助理与范围，进入详情可暂停或撤销。
- **活动与诊断**：查看数据访问、关闭诊断原文、删除诊断内容；默认不保存个人正文到诊断记录。

私人笔记标记不是装饰；含 N01 的请求若不满足策略，界面指出“有 1 份私人笔记未包含”，不能先发送再提醒。用户移除正文后可以继续使用其他允许字段。

### PRIV02 本次数据流向（详情抽屉；必须可从生成入口打开）

标题“这次将发送什么”，第一屏展示：

| 区块 | 连贯示例 |
| --- | --- |
| 用途 | “改写作品集案例说明” |
| 接收方 | Core 选定 provider，或 Harness 会话/工具日志及当前 agent 路由；显示实际地址/保留边界，后续换模型可能重用历史 |
| 将发送 | G01 标题、成功标准；N02 本次粘贴的案例草稿；必要的语言要求 |
| 不包含 | N01 私人笔记、其他目标、日历详情、凭据 |
| 选择 | 默认“仅这一次”；“以后对同类内容也允许”需单独选择并展开具体规则 |
| 主动作 | “发送这些内容”；次动作“返回修改”“取消” |

内容清单可逐项展开实际文本或附件名称；不只展示“3 条数据”。删除某项后若建议能力受影响，写“缺少案例草稿，只能提供通用写作建议”，让用户选择。发送前改用不同服务、添加笔记或更改范围时，旧同意失效，重新展示摘要。

“发送这些内容”只授予明确的一次导出，不批准计划变更；未点击不发送。走受限 Core 本地预览时无需重复打断已有授权；走 Harness agent 时，即使当前本地模型也需说明工具历史保留/换模型风险，device_only 不因此放行。无法保证后续目的地时不传该材料，可仅在人工详情查看，不能用“仅一次”承诺已入日志正文以后不被重用。

云端流式生成过程中无法保证撤回已经发送的内容。点击“停止生成”后写“已停止后续生成；已发送的内容无法从此处撤回”，不显示“已撤回所有数据”。

## 6. 外部助理：连接、限权、暂停和撤销

### AG01 外部助理（主要页面；D06 代表画面）

空态：“还没有外部助理连接”；主动作“添加助理”，说明“你可以限定它能看什么、能做什么”。非空列表每行显示名称、连接状态、可访问范围、最近访问时间，避免只显示一个“已连接”图标。

A01 行示例：“桌面助理 / 已授权 / 仅作品集第二版 / 可读取、可提出建议 / 不可直接修改”。最近活动“09:32 读取了 5 项任务”。列表提供“查看授权”，暂停和撤销在详情中，防止误触。

### AG02 连接授权（宿主完整详情；手机整页仅为后续 Flutter）

标题“允许桌面助理访问哪些内容？”，依次展示：

1. **是谁**：连接名称、来源应用/地址；未验证来源写“来源尚未验证”，不能由对话里一句“我是可信助理”消除。
2. **范围**：仅 G01/P01；其它工作空间、收集箱与私人笔记默认不选。
3. **可读取**：五项任务标题、估时、状态、允许的空闲时间；可看实际示例。默认不给笔记正文、附件或全部日历标题。
4. **可操作**：默认“提出建议”；“创建少量任务”“调整日程”“删除事项”“向外部发送”分别授权，不用“完全访问”总开关吞并差异。
5. **有效时间**：本次演示选择“今天结束前”。支持具体截止与随时撤销，不能把关闭弹窗解释为批准。

说明：“结果可能写入 Harness 会话日志，并在后续换模型或继续对话时再次使用。”紧邻读取范围展示；当前模型本地不能覆盖这一风险，device_only 正文/标题/摘要仍按导出策略拒绝。人工 UI 可看与 agent 可读是两张授权面，人工 token 不透传给工具。

底部摘要“可读取作品集的 5 项任务、可提出建议；修改仍需你确认”。主按钮“允许这些访问”；次按钮“拒绝”。无勾选范围或身份验证未完成时，按钮不可激活并有具体原因。

### AG03 连接详情（主要页面或深链接详情路由）

上半部展示当前权限与有效期；下半部为“访问记录 / 提出的建议”。权限修改后保存为明确的新授权。缩小范围立即影响新读取及尚未执行的动作；不声称已读出的内容自动删除。

“暂停访问”短弹层说明“暂停后，这个助理不能继续读取或提交新内容。你可以稍后恢复。”主按钮“暂停访问”。恢复需核对当前范围；不自动续期已过期授权。

“撤销授权”短弹层列出 A01、其读取范围及尚未处理的提案数。文案：“停止后续访问。它之前读到的内容无法从这里收回。”主按钮“撤销授权”，次按钮“保留授权”。

撤销后列表显示“已撤销 · 09:39”；等待执行的操作停止并在记录里说明。若授权撤销发生在提交完成后，展示已提交事实与“查看修改”；不能伪装成已撤回。已保存、仅供本人查看的建议可保留，标注“来源授权已撤销”；若本人希望使用，动作是“复制为我的草稿”，重新检查范围与影响，不能直接沿用旧批准。

### AG04 活动记录（主要页面 + 单条详情抽屉）

时间线支持“读取 / 建议 / 已保存 / 未完成”筛选。记录写“桌面助理读取了作品集的 5 项任务”“提出了 2 处时间调整”“你应用了计划”，不把 agent 的提议写成用户完成事实。详情列实际范围、结果和去向，默认不展示敏感正文。

## 7. AI 澄清、预览和提交的连续主流程

### AI01 入口与生成（嵌入主页面）

G01 指令输入：“把这些工作排到月底，尽量放在上午，每天不超过一小时。会议保持不动。”输入旁的处理位置是可点击摘要，不是只读盾牌图标。主动作“预览安排”，输入始终可编辑。

阶段反馈使用实际状态：“正在整理你的要求”“正在检查可用时间”。显示“停止生成”，不使用虚构进度百分比。用户离开后，在“活动”查看长任务；重新打开不会丢草稿。

### AI02 需要澄清（详情抽屉顶部，保留来源目标）

标题“还需要确认一件事”，问题“周末也可以为作品集安排时间吗？”；选项：

- “只安排工作日”。
- “本周六可以，周日不安排”。
- “周六和周日都可以”。
- 文本入口“补充其他要求”。

演示选择第二项，成为本次安排条件；另有未勾选的“保存为以后默认”。不把一次回答升级为永久偏好。底部“继续预览”“先保存草稿”。用户没有回答时可保留未排入事项，不能推断为同意周末工作。

### AI03 计划预览（完整抽屉；D04 / M01）

顶部“作品集 · 计划预览”，紧邻状态“尚未应用”。摘要“安排 5 段，共 4 小时；两场项目沟通保持原位”。时间范围“10 月 24 日—10 月 31 日，上海时间”。显示五段 S01–S05；点击每行可看目标、估时来源、依赖与允许时段。

分区顺序：

1. **本次变化**：新增五段分配；若只是排入已有任务，不写“新增 5 个任务”。
2. **保持的安排**：C01、C02 与锁定事项。
3. **未排入**：完整方案写“无”；局部方案列剩余分钟与原因，不能隐藏。
4. **本次条件**：每天最多 1 小时、尽量上午、本周六允许、周日不安排。
5. **还可以调整**：时间行“更改时间”，每项“这次不安排”；不要求拖拽。

底部固定主按钮“应用这份安排”；次按钮“继续调整”；文本动作“放弃预览”。“应用”始终在看得见的差异之后，不放在初次生成状态。

Harness 窄容器使用逐项议程与可展开差异，不缩小周网格；长清单主动作不遮末行，读屏明确原/新时间。旧 M01 仅作后续 Flutter 手机/窄屏参考，其图上是单项邮件改期，并非此处完整五段方案的截图；首期插件新布局仍待绘制。

### AI04 不可行与局部方案（预览内状态）

在另一个演示分支，用户明确取消每日 1 小时上限，改为“只使用今天 14:00–15:30 这段时间完成 4 小时”。B01 的 90 分钟不可容纳全部工作，标题“有 2 小时 30 分钟暂时放不下”；保留原估时，不缩减为 90 分钟。选项“允许其他日期”“减少本次范围”“只保存任务”。如果选择局部安排，主按钮写“应用这 90 分钟”，明确未排入部分，不能仍写“完成全部安排”。

固定会议冲突时显示“与 10:00–11:00 的项目沟通重叠”，提供“保持会议，重新安排”“手动选择时间”。不以高优先级或模型确定程度覆盖锁定。

### AI05 预览过期（预览内行内条）

09:28 同一 Core 的另一已授权客户端把 10/26 10:00–10:45 标不可用，不暗示已实现多设备同步。旧预览显示“安排依据已变化，需要重新检查”，应用停用、候选可读；动作“重新检查/返回调整”。

新建议将 T02 改为 10/26 11:00–11:45，其余四段不动。只显示新增的这处变化，并说明“10:00 的时间已不可用”。需要用户重新点“应用这份安排”，不会沿用旧按钮点击或之前同意。若时区、日期解释、模型处理规则变化，同样重新检查对应部分。

### AI06 保存中、成功与结果不明

正常路径：可信人工面点击应用 → Host RPC bridge 注入人工上下文并绑定 Core 批准 → Core 重验版本/授权提交 → 持久回执后“安排已保存”。宿主工具审批不自动变成这次批准，批准凭据不进 agent 结果。摘要“5 段已加入日程”，任务仍未完成；提醒/effects 独立。

如果网络在提交之后断开，显示“正在确认是否已保存”，先查结果，不能让用户反复创建计划。已保存则显示原结果；确知未保存后才提供“重试保存”。未知状态不写“保存失败，请再次提交”。

“撤销这次安排”创建新的变更预览：说明删除哪些分配、已开始或后来修改的哪些项目需要保留。不能撤销已发生的工作事实或假称收回外部已发送通知。

计划保存但提醒设置失败时，显示“安排已保存，提醒尚未设置”，动作“处理提醒”。不回滚已存计划，也不把整项标作失败。

### AI07 失败、停止与输入保留

| 失败类别 | 主文案 | 动作与边界 |
| --- | --- | --- |
| 模型不可用 | “暂时无法生成建议，输入内容已保留” | 重试 / 手动安排；云端仅在明确选择后打开数据流向 |
| 缺信息 | “还不知道‘下周找一天’指哪一天” | 给出选择或保留未知；不红色归咎用户 |
| 权限不足 | “当前授权不允许修改这些事项” | 查看范围 / 仅保存建议；不自动扩大范围 |
| 处理规则变化 | “处理方式已更新，请重新检查这份建议” | 重新检查 / 返回修改；已撤销的云端同意不可复用 |
| 已知保存失败 | “尚未保存，原来的日程没有改变” | 重试保存 / 返回调整；仅用于确认未提交的失败 |
| Web 离线 | “当前离线，草稿只保存在这个浏览器” | 继续编辑 / 联网后检查；不能显示“已加入日程” |
| Harness 断网但 Core 可达 | “云端暂不可用，可用本地功能保留” | 按实际 Core 能力手工/本地处理，不把浏览器断开 Core 当已提交 |
| 后续 Flutter 原生离线 | 另行验证本地管理与模型能力 | 不由 Harness 网页或 Electron 外壳直接兑现后台/提醒/离线库 |

“停止生成”后，预览生成路径显示“已停止，输入仍在”；若收集箱原文早已保存，则写“收集内容已保留”。不能把停止解读为删除已有事实。提交已经完成时显示真实结果，停止按钮不承诺回滚。

## 8. 数据与备份：导入、导出、恢复

### DATA01 数据与备份（主要页面）

主区三个明确入口“导入事项”“导出数据”“从备份恢复”，下方显示最近成功备份和文件位置（仅可访问时）。未创建备份写“尚未备份”；不能显示编造的定时状态。导入是增加或合并选择的内容，恢复是替换当前业务快照，两者不共用模糊的“打开文件”。

本规格设计 Zodo 备份、CSV 任务和日历占用快照的流程；具体格式只有实现与验证后开放，尚未支持的格式明确写“暂不支持此格式”。不在原型中伪造文件解析成功。

### DATA02 导入向导（三步主要页面）

1. **选择内容**：选择文件、显示文件名与来源；说明“先检查，不会立即修改”。不直接打开旧项目正在使用的数据库。
2. **检查映射与问题**：展示标题、日期、估时、项目、来源；缺失值保持未知。歧义日期要确认，缺标题要补全，重复显示匹配依据。私有笔记不会因导入自动允许云端读取。
3. **确认导入范围**：计数、去向、重复处理和未导入问题；主按钮明确数量，成功后可查看结果与未导入项。

统一演示文件“作品集_补充任务.csv”有三行：

| 原行 | 内容 | 检查结果 |
| --- | --- | --- |
| 1 | 筛选 3 个项目素材，45 分钟 | 与 T01 有相同来源标识，跳过重复 |
| 2 | 整理参考链接，15 分钟 | 可新增至收集箱，不自动加入 G01 的 4 小时计划 |
| 3 | 标题为空，备注“准备介绍稿” | 需补全；备注不能自动变成确定标题 |

摘要“1 条可新增 · 1 条重复 · 1 条需补全”。用户可修正第三行或选择“只导入这 1 条”。排除项明确列出，不能将无效记录静默丢弃。成功文案“已导入 1 条；1 条重复已跳过，1 条未导入”，提供“查看新增事项”“导出问题清单”。选定的有效集合一次保存，失败不出现半批写入。

重新导入同一文件时，已经导入的第二行也被识别为重复；不再次创建。导入错误保留映射和修正结果，给出可重试范围。

### DATA03 导出选项（详情抽屉）

标题“导出哪些内容？”，范围为整个工作空间或所选目标，格式按支持情况提供。清单显示是否含笔记正文、附件和历史记录；默认不包含密钥、有效授权或诊断原文。提示实际风险“导出文件可被拿到文件的人读取”，不虚构端到端加密标志。

底部“创建导出文件”，Core/Host 生成及实际下载/保存完成前不写“已备份”。展示名称、大小和受支持下载/保存动作；不让浏览器任意写 Host 文件路径。后续 Flutter 手机再接系统分享。取消只显示“已生成、尚未保存”，不更新最近备份时间；文件正文不作为 agent 工具结果自动返回。

### DATA04 从备份恢复（三步主要页面 + 最终短确认）

检查页显示备份时间“2026-10-24 09:10，上海时间”、来源设备、数据数量和兼容性；当前时间演示为 09:40。不兼容、损坏或缺少必要部分时停止恢复，保留当前数据并可查看问题。

对比页写“将使用 09:10 的事项替换当前事项”，分列目标、任务、日程、执行记录的变化；演示对比为“移除刚加入的 5 段日程，保留备份中的 5 项任务”。若 CSV 导入分支也已执行，另显示“移除导入的参考链接”。不能凭文件日期暗示恢复一定完整。

恢复不恢复 provider 密钥或外部助理有效授权；连接与隐私保护按当前设备重新检查。展示“外部助理需要重新授权”，避免旧备份使撤销的访问复活。

最终确认：“恢复前会先保存当前快照。恢复后可以返回这次操作前的状态。”只有安全快照实际完成后，才激活“恢复这份备份”。无需为每次恢复让用户抄写长句；清楚列影响、用明确按钮和可回退机制。主按钮“恢复这份备份”，次按钮“返回检查”。

恢复中页面显示阶段并避免编辑被替换的工作空间；成功后“已恢复到 09:10 的备份”，动作“查看事项”“查看恢复前快照”。失败则“恢复未完成，当前事项仍保留”，提供重试或问题详情；结果未知先核对，不同时展示新旧混合列表。

## 10. 设计验收清单

- 页面、抽屉、弹层有唯一入口和返回位置；关闭后回到触发控件，草稿不丢。
- 每个主按钮都能回答“对哪些内容做什么”；不可点击时有文字原因。
- 加载、空、失败、过期、离线和结果未知均有对应状态，不靠一个通用报错覆盖。
- 预览与提交、保存与提醒、安排与完成、暂停与撤权、导入与恢复分别表达。

## 11. 宿主重载、回放与持久恢复的验收

关闭 Zodo tab、切会话、卸载/热重载插件时释放 Slots、订阅和 UI effect；已持久化 Core 事实、Proposal、Run、receipt、outbox 不删除。未提交草稿仅在明确的安全草稿存储保存，不能写进共享会话日志当备份。Core 保持运行才可能继续工作，Core/Host 一并停止时不承诺推理不断。

重挂载先核对人工身份、workspace、policy_revision，再取 Core 快照、cursor 和原操作回执。状态未知先查 receipt，不由 React effect、RPC 自动重连或宿主历史回放再次执行写命令；需要重试时沿用原幂等键，内容修改产生新提案/批准。未知外部送达先对账，不随重连再发通知。

宿主会话/Conversation 回放可呈现安全摘要与已有对象链接，但只做读取。人工详情可读的私密字段不自动进工具结果/审计导出；模型切换、grant 撤销、会话续接都重新检查 agent 结果导出。至少验证关闭后重开、热重载、同对象双客户端修改、撤权后恢复、提交后断线及模型切换六种场景；这些均未实施通过。
