# 新项目实施顺序与退出标准

版本 1.3 · 2026年10月24日 · 实施规划，尚未执行产品开发。

## 完整目标与执行顺序

Rust 独立个人事务 AI 内核是完整产品的权威核心；首期通过 Harness 原生工具与 React UI 插件交付，Flutter 作为后续独立跨平台客户端。P0、P1、P2 与 Flutter 均属于本计划，完成 P0 或插件接入不代表整个目标完成。唯一视觉方向仍为“清晰日程”。

以下资料路径均以本包根目录为基准。先读 `spec/06-harness-adapter-and-ui.md`、`contracts/HARNESS_BRIDGE.md`、`implementation/HARNESS_TEST_MATRIX.csv`，再结合领域、运行契约、30屏幕族、16类弹层与关键场景实施。版本1.3的新宿主决策优先于旧稿中“首期先做Flutter”的顺序；旧图保留业务内容与视觉参考，不决定宿主API。

30个屏幕族和16类弹层是业务目的地与交互能力，不要求30个顶层窗口。它们在 Zodo 插件内部映射为页面、视图、详情和弹层；不把Zodo的五个业务入口强加为Harness全局导航，也不能把菜单名称计作功能实现。宿主无对应扩展点时，在受支持的插件表面调整布局并记录ADR，保留相同业务可达性。

实施以 A0—A7 连续推进；可并行完成互不依赖工作。某阶段未通过的依赖不得被后续界面掩盖，但单个平台或账号阻塞也不应停止其余工作。

## A0 宿主扩展与进程连接最小验证

本包没有已验证的 Harness 源码版本或可用插件工程。先确认宿主来源、版本/提交、许可证、插件清单、React扩展表面、原生工具注册、调用身份、会话交互、进程与网络能力；读取实际官方说明和源码，锁定可复现版本，不把设想的API写成已存在能力。

建立最小插件和 Rust 测试进程：原生工具传入结构化请求，React表面显示可验证结果，经过真实宿主会话调用一次；再验证异步结果/取消、插件重载、宿主退出重启、断连与第二实例。测试进程只证明桥接能力，不作为业务内核。确认主进程/沙盒/浏览器上下文的能力边界，选择受控IPC或认证本地HTTP；UI不直接打开SQLite或凭据文件。

明确运行时所有权：谁启动、发现、连接和关闭daemon；宿主退出时按已记录策略继续允许的任务或检查点停机，不泄漏孤儿进程，不承诺宿主关闭后无限运行。宿主工具的可信身份来自受验证上下文，不能接受模型或React自报actor/批准。

交付版本锁定、最小源码、启动命令、实际宿主记录、能力矩阵和桥接ADR。退出要求是真实宿主加载、原生工具与React往返、实际会话调用及退出/重启记录全部具备；仅HTTP脚本或浏览器开发服务器成功不算宿主接入通过。若宿主有硬限制，记录最小缺口并继续A1等独立工作，不私自改回首期Flutter。

## A1 Rust 无 UI 基础纵切

建立可复现workspace、共享schema/DTO、时钟与模型端口、SQLite适配、CLI和CI。`zodo-kernel` 保留领域/应用/智能工作流，不依赖 Harness、React、数据库行、MCP或模型SDK；`zodo-runtime` 实现存储、模型、Run、effects及服务入口；Flutter FFI crate在A5启用，不提前增加移动打包负担。

实现收集、目标/项目/任务与DAG、时间类型、固定预约/容量/分配、Proposal/Run、批准/授权、单写者、revision、幂等回执和outbox。以固定时钟和隔离测试库验证“收集→候选→校验→提交→执行记录→简单回顾”，先用fake model隔离规则，再在A2/A3接真实模型。

硬不变量从此阶段执行：预览不写正式事实；过去、已开始和锁定安排不自动移动；容量内部不重复扣全局占用；无解如实保留未排入；任务完成与专注结束分离。业务变更、批准消费、回执及outbox同事务；网络/推理在事务外。

退出要求：不启动 Harness、React、Flutter也能运行；重启后事实、Run、回执可恢复；并发、旧提案、同键不同请求、撤权、写入故障、取消前后边界与未知外部送达均有独立结果。fake通过只记规则验证，不记模型或产品验收。

## A2 Harness 原生工具与 React 界面真实 P0 闭环

将宿主原生工具、React插件和CLI接入同一应用契约、同一workspace与单写者。插件只是适配器；React管理导航、草稿、查询投影、输入/可达性，业务规则和提交仍在Rust。宿主会话中的agent可直接提议结构化变更，不必再调用内置模型重新解释。

按逐屏矩阵实现P0目的地及弹层，包括手工管理、收集澄清、目标拆解、任务依赖、计划比较/诊断/过期、确认与回执、专注/进度、反馈/简单回顾、模型隐私/授权和操作恢复。补齐基础循环与单次例外、耐久提醒意图、busy快照。七张图仅为关键帧，其余页面以真实可操作组件展开，不嵌入整张图充当UI。

完成一次真实宿主会话的“用户目标→原生工具→Rust提案→React比较/用户批准→提交→执行反馈→回顾”，同时验证无模型手工路径。正常、取消、失败、不可行、过期、权限变化和送达未完成均有去路。中文IME组合不推理、输入可编辑、最新请求合并、旧结果丢弃、焦点/键盘/缩放均在实际宿主内验证。

退出要求：P0实际操作经过宿主、桥接、真实Rust状态和持久回执；宿主会话真实模型调用与UI动作可追溯；Harness原生工具与CLI得到一致事实/错误；宿主卸载/重载/退出不造成半提交。A2是首个真实闭环，只有A3全部P0缺口关闭后才宣布P0整体完成。

## A3 模型 MCP 恢复与隐私的完整 P0

分别实现并验证模型路径：Harness会话驱动原生工具；Zodo受策略控制的本地/云端ModelGateway；如宿主支持UI委托会话推理，再验证该可选路线。不得将“宿主已配置模型”当作Zodo本地/云端路径均通过。记录实际模型/provider、调用位置、上下文、超时、取消、成本/内存和下一次真实请求使用的设置。

`local_only` 不静默云回退，`device_only` 不因自托管或本机工具入口而自动外发。进入宿主会话也属于潜在模型数据流：无法确认provider和上下文边界时，不宣称设备内处理。过滤发生在构建prompt、工具响应、附件和日志之前；代理权限与模型路由分别授权。

补MCP适配与真实目标client会话验证，复用同一runtime，不另建数据库/模型。锁定宿主、SDK、协议与模型版本后测兼容；MCP不是Harness原生工具的同义词。长Run与宿主会话生命周期解耦，验证取消、宿主退出、daemon崩溃/重启、事件缺口、并发客户端、过期批准和撤权后恢复。提醒及日历效果单独追踪pending/failed/needs_reconciliation，首个发布平台完成真实通知/恢复。

退出要求：冻结的真实模型集与独立约束检验通过；本地和授权云端、宿主会话、MCP均有实际调用证据；敏感字段在捕获的实际传输中不存在；至少一个发布平台安装、启动、重启、权限和副作用验证通过。账号、网络或额度缺失明确阻塞对应行，不能以skip、fake或缩小样本关闭P0。

## A4 P1 完整个人事务能力

完成复杂循环/系列编辑/完成后间隔、习惯与周期配额、批量编辑、保存查询、完整搜索、标签/上下文、资料引用、统计、丰富回顾、剩余量校准、增量日历/冲突对账、有限自动化、导入导出、备份恢复和支持平台的通知/专注恢复。稳定性代价权重是优化；过去/已开始/锁定不自动移动早已是P0约束。

对30屏/16弹层逐项核对：入口、字段、正常/异常、返回、状态保留和可达性都有真实实现；多个目的地可复用插件子视图，但不能遗漏任务总览、搜索、数据恢复或授权设置。覆盖表保留文字设计、视觉、可交互、真实内核、平台验证的独立状态。

退出要求：P1全部条目有独立断言与实际宿主操作证据；用覆盖一周的代表性事务序列复盘，固定时钟回放验证规则，真实使用验证另记，不把演示数据冒充实际使用。重复导入、损坏备份、系列例外、配额撤销、对账失败和规则循环有恢复测试。真实账号集成缺凭据时继续其余功能，相关集成仍保持未完成。

## A5 Flutter 后续独立跨平台客户端

Flutter仍属完整目标，不是将来可选建议。以共享KernelClient/契约接入同一Rust应用能力，沿清晰日程实现同等30屏/16弹层及流程；布局按桌面、手机、平板调整，不复制宿主外壳。不得要求运行Harness才能使用独立Flutter客户端或Rust核心。

桌面连接权威daemon；Android/iOS按验证后的嵌入FFI与平台生命周期适配；Web连接认证runtime，离线仅为缓存/未提交草稿。核实并锁定FFI、链接、签名、安装和模型依赖，不把宿主平台通过外推为Flutter平台通过。原生通知/后台/挂起恢复、安全存储和深链分别验证。

退出要求：Windows、macOS、Linux、Android、iOS、Web逐平台记录实际支持范围；桌面/手机实操、Flutter检查、打包安装、重启/恢复、可达性与共享协议一致性均有证据。缺设备/签名/runner的行仍未验证；先推进可测平台、UI与核心工作，不把整阶段标完或无限等待单一平台。

## A6 P2 深化与互联

实现有界跨周期依赖/跨系列规划、扩展自动化与连接器、多设备身份/同步/加密/冲突合并，以及经授权的更广外部执行和个人会议协调。按ADR先把“高级/更多/全部”等模糊用语收敛成有限功能、支持provider/版本、规划窗口、设备角色与验收样本；定义不能是空集合，也不能删除已承诺能力来凑完成。

验证至少两个独立客户端/设备的离线修改、重连、冲突、撤权与恢复，不把共享单库当多设备同步。同步旧授权/已撤销凭据不能复活；未知外部送达不盲重试。每个连接器和执行动作明确范围、预算、批准、幂等和失败补偿。先独立威胁模型，再开放真实写入；不因模型会调用工具而绕过领域权限。

退出要求：每个冻结的P2能力在Harness及适用的Flutter入口完成真实用例与故障验证；明确不可逆效果和各平台差异。无法测试的设备、provider或额度继续记录阻塞，不降格成“已有扩展点”即完成。

## A7 全部能力回归与最终验收

在候选提交上逐项核对P0/P1/P2、Harness与Flutter全部目标；修复回归并重跑受影响检查。运行Rust格式、严格Clippy、适当all-targets测试，React/插件类型与构建、交互测试，Flutter分析/相关测试、协议兼容、真实模型eval、安装恢复及平台矩阵。每项记录实际命令、退出码、环境、原始输出和产物身份；CI与人工/设备实测分别记录。

最终以真实用户路径验证所有业务能力与手工退路，含宿主会话、宿主退出/重启、模型切换、并发、权限、循环/时间、备份/同步及副作用。模拟仅用于可控故障/单元测试；静态图、通过的设置页、局部测试或仅构建成功不能替代集成验收。

仅当覆盖账本所有目标行有证据通过，或用户明确修改范围后，才可宣布完整目标完成。不得把未测、skip、known issue、配额耗尽或平台阻塞折算为通过。交付实现、测试证据、实际能力表、运行/恢复说明和剩余限制；发现缺口就继续相应阶段。
