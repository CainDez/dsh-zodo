# Zodo 完整 UI 页面与闭环流转规格

版本 1.3 · 2026-10-24 · 状态：Harness 首期 UI 插件设计交付，尚未实施产品代码。

本规格保留 30 个屏幕族、16 弹层、8 条闭环的稳定 ID 与业务语义。用户已确认首期载体为 Harness 内 Zodo 工作台、详情与批准视图；独立 Rust Core 和全功能目标不变，Flutter 后续作为独立客户端。当前交付为“完整文字规范 + 旧清晰日程视觉参考”，没有 Harness 插件新截图或已实现控件，不是全 30 页高保真。屏幕族是用户目的与行为，不要求每个都成为宿主全局路由。

依据为 [产品与总体架构](spec/01-product-and-architecture.md)、[领域与能力](spec/02-domain-and-capabilities.md)、[运行时契约](spec/03-runtime-contracts-and-platforms.md)、[UI 与交付](spec/04-ui-product-and-delivery.md)、[架构决策](spec/05-architecture-decisions.md)。这些文件是业务与协议基线；本文件细化界面，不改变 P0/P1/P2 边界。已选定的清晰日程采用这份信息架构与行为，不把聊天或 MCP 接入称为独有能力。

## 1. 不可违反的产品语义

1. **提案与事实分开。** 未取得有效批准，不修改正式任务、目标或计划。有效批准来自本次用户确认或既有、可检查的显式预授权；模型自报、host 已确认提示、`approved:true` 均不能代替内核校验。保存输入草稿、用户明确收集原文、持久化 Proposal/Run 是独立行为，不能伪装成任务已经创建。
2. **正式状态以回执为准。** 仅 `committed` 回执使界面显示已应用；传输成功、模型生成结束、按钮动画均不代表提交成功。提醒与日历效果另显 pending、delivered、failed 或 needs_reconciliation。
3. **目标、任务、日程、执行不同。** 任务完成不证明目标达成；计时结束不完成任务；固定预约、容量块和内部任务分配分别展示且不重复计量。目标/项目可为空，独立待办无需先建项目。
4. **时间含义不混用。** 界面区分“期望完成”“必须完成”“最早开始”和“偏好时段”；日期/当地钟点/绝对时刻及时区可追溯。全天任务不占满全天。明确硬边界无法满足时报告不可行，不偷偷改成软偏好。
5. **人工控制可持续。** 已开始、过去、锁定分配不自动移动；手动调整明确作用范围。用户可拒绝、局部修改、重算和撤销可逆变更。已经提交的撤销是新补偿操作，不能承诺撤回已发通知。
6. **人工 UI 与模型视图分开。** 展示 Core/runtime 所在位置、workspace 和真实调用身份。人工能读不表示 agent 能读；工具结果可能进入 Harness 会话日志并在后续换模型时重用。device_only 不因当前模型本地而允许进入 agent 历史；字段/目的地/保留边界须在桥接输出和模型请求前校验，不能先返回正文再提示。
7. **无模型仍可管理。** Core 可达时收集、手工编辑、查询、执行记录及明确提交保持可用，模型失败不清空输入。Harness 浏览器断开 Core 时只显示缓存/未提交草稿；原生离线、后台和通知属于后续 Flutter/平台验证，不能由网页直接承诺。
8. **宿主生命周期不接管事实。** 关闭会话、收起面板或热重载仅卸载 UI/订阅；Core 持久对象、Proposal、Run、receipt 和 outbox 不随之删除。若 Core 自身停止则按 Core 恢复协议处理，不承诺推理继续。宿主历史回放只重建显示，不能自动重提案、重新批准或 execute。

## 2. 信息架构、导航与共享框架

首期五个业务入口为**今天、收集箱、目标、日程、回顾**，仅在 Harness 插件自有工作台内组织，可为内部分段/局部导航，不夺取或改造宿主全局导航。目标以“目标/项目”到 S05/S07，回顾以“回顾/习惯”到 S22/S23；Tasks 从今天“全部任务”、插件搜索和获准的宿主命令到 S09。Zodo Settings 由插件入口打开，分类及人工权限属于 Zodo，不代替宿主设置。

首期专注从今天/任务详情及插件迷你条打开，Proposal/Run 从角标/活动卡进入宿主支持的详情面。搜索/收集只在插件区或宿主正式扩展点可达，不覆盖宿主快捷键。五入口不减少 30 个逻辑屏幕族；后续 Flutter 手机才采用独立五底栏和原生返回/安全区规则，Harness 窄面板不冒充手机应用。

详情保留来源、筛选和滚动；内部地址先校验 workspace/权限，对象不存在/归档/不可读分别呈现。由宿主拥有的 Esc/模态服务处理最上层退出与焦点恢复，插件不抢占全局处理器。局部筛选/日期可进入可恢复的插件导航状态，敏感正文、密钥和附件路径不进 URL；返回不清空草稿。

React + 宿主 Slots 构成局部工作台、详情/批准面与反馈区；经注入的 Client service/Host RPC bridge 访问 Rust Core。React 只保留投影、草稿与焦点，Cordis 只提供接线/生命周期，不承接业务事实与规则。每屏一个主动作，危险/批量动作有影响摘要；技术信息在诊断展开。具体 Slot/tab ID 与 props 在锁定宿主版本后验证，不虚构通用 root 或 Runtime API。

## 3. 跨端适配规则

| 条件 | 布局与交互 |
| --- | --- |
| Harness 宽工作台 | 按插件容器实际宽度用主区 + 可选详情/提案双栏，不复制原图全局侧栏；比较始终有逐项差异 |
| Harness 中/窄停靠面 | 内部分段导航、摘要 + 可返回详情；长审查打开宿主支持的完整详情面；容器变化不重启生成或丢草稿 |
| 宿主分栏/浮出/收起 | 保留对象和投影；重挂载按快照/receipt 恢复，不能由 useEffect 或历史回放重新 execute |
| 后续 Flutter 桌面/平板/手机 | 再验证独立三栏/双栏/单栏、手机五底栏、系统返回及触控；M01 仅为信息层级参考，非首期能力证据 |
| 文字放大/分屏/软键盘 | 根据可用内容宽度重排，非仅识别设备名称；至少验证 200% 文字、横竖屏、键盘遮挡、安全区；主动作可滚动到达 |
| Harness Web/桌面宿主 | Core、Host 和浏览器位置分别说明；断线明确“未提交/结果待确认”，重新认证不静默扩大授权；网页不兑现原生后台 |

拖拽仅为加速手段，提供“移动到”“调整时间”“更改依赖”等按钮替代。Harness 窄容器及后续手机都以关系列表替代不可读依赖大图；Schedule 的日/周、空闲及未排入保持同一来源，不因容器变窄删掉诊断。

可达性要求：可见焦点、稳定焦点顺序、读屏名称与状态、足够对比度、颜色之外的状态文字、约 48 逻辑像素触控目标、减少动效和图表文字等价内容。对自动预览按阶段播报，不逐 token 读出；新建议不夺取输入焦点。

## 4. 30 个屏幕族

`Sxx` 是稳定逻辑屏幕编号，`Lxx` 是第 5 节弹层编号；视觉帧另用 `D01–D06`（桌面）与 `M01`（手机），三类编号不可互换。下面路径是信息架构示意，尚未实现。P1 页面也必须具备设计，P0 产品可按明确能力标记呈现，不能展示可点击却无结果的占位按钮。页面的公共失败/离线行为见第 6 节；表中列出其特有恢复方式。

| ID / 屏幕与示意路径 | 主要信息及主动作 | 次动作 | 退出、失败与恢复 |
| --- | --- | --- | --- |
| S01 首次进入与工作空间 `/welcome` | Harness 插件内连接的 Core、空白/演示空间、时区与隐私；主动作“建立/连接工作空间” | 先手动使用；检查 Host/Core 位置 | 不把宿主会话自动当个人 workspace；连接失败保留参数；演示隔离；无模型不阻止手工；初始化提交后查回执，不重复创建 |
| S02 Today `/today` | 当前会话、固定承诺、可用容量、下一步、风险；主动作随上下文为“继续专注/开始下一步” | 快速收集；记录进度；看今日计划；解释推荐 | 推荐为空说明原因并进入 Inbox/Tasks；模型失败保留确定性承诺与任务；正在执行内容不因重排消失；离页不停止专注 |
| S03 Inbox `/inbox` | 未处理/待澄清/已处理原文、来源与转化引用；主动作“处理所选” | 收集；筛选；忽略；查看来源 | 忽略有可恢复记录；批量转化先预览；单项失败不丢原文；退出保留当前项；处理完成后链接新对象 |
| S04 收集与理解工作区 `/capture/:draft` | 可编辑输入、候选类型/字段、缺失/推断、运行位置；主动作“查看变更/提交明确录入” | 只存 Inbox；手工填写；取消本次解析；选模型 | IME/最新输入规则见第 7 节；退出保存草稿或明确放弃；预览不写任务；模型失败可继续手动；多任务进入 S16 |
| S05 Goals 目标列表 `/goals` | 活跃/暂停/达成目标、成功标准摘要、风险；主动作“创建目标” | 搜索；切状态；排序；查看独立项目 | 空状态不强迫建目标；达成须确认/证据，不能用完成率自动修改；旧数据/权限失效刷新后再操作 |
| S06 目标详情与拆解 `/goals/:id` | 目标结果、标准、关联项目、里程碑、证据及假设；主动作“生成/调整方案” | 编辑；暂停；记录证据；标记达成；查看回顾 | AI 拆解进入 S16，原目标不先改；丢失权限返回列表并保护允许保留的草稿；达成/重开是明确操作 |
| S07 Projects 项目列表 `/projects` | 项目范围、下一步、阻塞、目标引用；主动作“新建项目” | 按目标/标签筛选；归档；查看取消项目 | 不要求绑定目标；取消项目不静默完成其任务；批量归档提示影响；退出保留查询与排序 |
| S08 项目工作区 `/projects/:id` | 层级任务、里程碑、依赖/阻塞、剩余量、资料引用；主动作“添加下一步/拆解” | 列表/依赖视图；编辑项目；提议排程；关联笔记 | 依赖成环拒绝且原图不变；汇总父任务不重复估时；Harness 窄容器提供关系列表；未保存编辑离开前可存草稿 |
| S09 Tasks 全部任务 `/tasks` | 独立/项目任务、open/in_progress/done、blocked 和未排程状态；主动作“新增任务” | 快速完成/重开；排序；批量编辑；筛选 | 手工保存走相同权限/版本校验；完成和删除分开；筛选为空可一键清除；批量修改按阶段能力开放 |
| S10 任务详情 `/tasks/:id` | 动作、剩余量、优先级、时间强度、依赖、分配、来源/记录、提醒；主动作“开始/继续” | 编辑；完成；重开；记录阻塞；安排；归档 | 编辑并发冲突进入 S19；计时不自动完成；明确区分取消任务和结束循环；通知失败不撤销已保存任务 |
| S11 Zodo 搜索 `/search` | 插件内任务/目标/项目/资料结果与权限范围；主动作“打开结果” | 切类型；精确条件；清除；获准宿主命令入口 | 不替换宿主全局搜索；人工可见摘要不自动回给 agent；查询取消保留词；索引重建显示新鲜度；无结果能返回 |
| S12 条件构建与保存视图 `/filters` | 项目、状态、标签、日期/截止强度、剩余量、可执行性等条件；主动作“应用筛选” | 保存/命名/复制；查看自然语言解释；重置 | 保存查询为 P1；无法解析的自然语言保留为待确认条件，不伪装精确过滤；退出保留未应用草稿；查询不写任务 |
| S13 Schedule 日/周计划 `/schedule` | busy/固定预约、容量块、内部任务、未排入量、锁定与新鲜度；主动作“生成/调整计划” | 切日期/视图；新增预约/容量；锁定；刷新 busy | AI/拖拽产生候选差异，不先改正式计划；旧日历提示新鲜度；无解保留原计划与未排入事项；窄容器议程有同等信息 |
| S14 时间对象详情 `/time/:type/:id` | 明示 Commitment/CapacityBlock/Allocation 类型、时间/时区、包含关系与锁定；主动作“调整时间/分配” | 选择块内任务；锁定/解锁；移除；查看来源 | 外部事件先只读；内部 allocation 不再次扣全局容量；编辑锁定需明确解锁；跨日/DST 歧义进入澄清；关闭不应用候选 |
| S15 提案与工作流中心 `/activity` | 待处理 Proposal、queued/running/waiting_input/interrupted Run，来源与预算摘要；主动作“继续待处理项” | 查看结果；取消计算；筛选；恢复 | 实时输入不逐键生成耐久 Run；断线可重连查询，终态不凭动画推断；原对象已变时标 stale；取消进入确认状态而非立即成功 |
| S16 提案比较 `/proposals/:id` | 意图、来源、假设、增删改、影响/未排入、时间锚点、数据流向；主动作“应用所选方案” | 修改；只看差异；替代候选；放弃；解释 | 未有效批准不改正式事实；部分选择需形成新提案并重校验；缺少信息到 S17、无解到 S18、过期到 S19；内容变更使原批准失效 |
| S17 澄清问题 `/proposals/:id/clarify` | 必要疑问、原文依据、候选答案、“保持未知”；主动作“更新候选” | 编辑原文；延后处理；退出留 Inbox | 不强迫猜日期；硬截止/时区歧义需解决才能相关提交；回答后重算影响；取消保留材料、不创建半套任务 |
| S18 冲突与容量诊断 `/proposals/:id/conflicts` | 冲突对象、硬/软来源、缺口、可行部分、放宽建议；主动作“修改约束并重算” | 保留未安排；比较替代；回到原计划 | 不让“忽略”跨过硬约束；放宽明确形成变化；无法满足仍能保存独立任务，不能假装计划可行；退出不覆盖原计划 |
| S19 过期提案与版本比较 `/proposals/:id/stale` | 旧依据、当前变化、冲突字段、原提案保留部分；主动作“基于最新数据重算” | 明确合并草案；查看他方修改；放弃 | 不以旧批准重试提交；合并产生新 hash/批准；POLICY_CHANGED 进入隐私复核；对象被删返回相应列表且说明原因 |
| S20 提交回执与效果 `/changes/:id` | 已提交对象链接、提交时间、来源、effects 送达/待对账状态；主动作“返回工作/打开结果” | 可逆变更撤销；查看审计；重试安全效果 | 结果未知先查询 receipt，不能换新键重复写入；回滚失败不显示部分成功；外部未知送达先对账，不盲重发；撤销是新操作 |
| S21 Focus 专注与进度 `/focus` | 运行/暂停会话、关联、实际时间、剩余量；主动作“开始/暂停/继续/结束” | 写进展；换关联；放弃；独立完成任务 | 宿主关闭/热重载后查 Core 会话；不凭组件墙钟补写事实；只一个运行会话；结束不自动完成；不承诺网页原生后台或持续推理 |
| S22 Review 回顾 `/reviews/:period` | 目标/承诺/实际对照、完成/阻塞/偏差、证据和调整候选；主动作“生成/确认调整提案” | 选日/周；修正记录；只读浏览；导出摘要 | P0 简单回顾、P1 丰富统计；模型失败仍展示事实；AI 推断标注；把偏好变规则须明确批准；生成报告不先改计划 |
| S23 Habits 习惯列表 `/habits` | 当期机会、实例、已记录活动、周期达标与跳过；主动作“记录本次/新建习惯” | 查看历史；补记；暂停；筛选 | 周配额为 P1，不伪造成每日任务；重复点击去重；跳过不算完成；更正记录可重算统计；离线记录按本地能力提交 |
| S24 习惯/循环详情 `/routines/:id` | 规则、起始/结束、时区、实例与例外、次数口径；主动作“编辑规则/当前实例” | 本次改期/跳过；结束系列；查看历史；撤销补记 | 范围必须为本次/本次及以后/全系列；保留已发生历史和发生键；月末/DST 策略可见；P0 基础循环，复杂规则按能力标记 |
| S25 设置总览与时间连接 `/settings` | Zodo 局部设置、Core 时区/窗口、busy、提醒效果和宿主/Core 能力；主动作“保存设置” | 刷新来源；查看提醒状态/宿主限制 | 不修改宿主全局设置；影响计划先提案；无平台适配不显示通知就绪；凭据不明文；Flutter 原生能力后验 |

| S29 Agents 连接与授权 `/settings/agents` | 真实 principal、人工/agent face、可读字段、可提议/提交/effects、有效期；主动作“建立/更新授权” | 暂停/撤销；审计；查看会话日志去向 | UI 认证不透传给工具；工具结果可能进日志/后续模型；device_only 默认拒绝该导出；撤权停后续操作，批准凭据独立 |
| S30 Audit 操作与恢复 `/settings/audit` | Core 回执、来源、Run、路由、效果与宿主会话的安全关联 ID；主动作“检查操作” | 筛选；打开对象；查询/恢复；裁剪诊断 | Core 为事实源；宿主回放不 execute；不将人工审计正文自动送 agent；游标缺口拉 Core 快照，未知效果先对账 |

S25 内的日历与通知为清晰可定位的子面板；S29 授权详情、S22 回顾报告、S24 实例详情均必须有独立链接和返回状态。它们共用屏幕族语义，不能因此漏掉详情设计。S12、S23/S24 高级配额、S28 及审计高级恢复属于渐进功能，完整 UI 包标明阶段，产品实现不超出基线承诺。

## 7. AI 输入、草稿与确认细则

编辑器支持普通文本、多行粘贴、手工修正候选和明确的“仅收集”。IME composing 期间禁止发起推理或用 Enter 提交；组合结束后以短防抖合并预览。防抖时间为待实测参数，不把固定毫秒值写成跨设备正确性条件。

每次编辑递增 input_revision，最新请求可取消/合并；旧结果只可记诊断，不覆盖输入或新结果。解析中、模型切换、离页和取消均保留草稿；提交复用同输入、同上下文、未过期的预览，避免重复推理。已显示候选若输入有变化应标“更新中”，不能继续用旧候选提交。

自动预览遵循已批准数据流策略，默认走受限 Core 预览；把材料发送 Harness agent 是另一条需独立导出检查的路径，不能自动复制到宿主 prompt/会话。首次云请求前显示 provider、Core/Host 位置与范围；当前本地路由不能保证未来日志不出设备。模型缺失/内存/下载/断线显示具体限制并保留手工；实际能力校验后才标可用。

澄清只询问影响目标或合法提交的歧义；“未知/稍后处理”是正常结果。相对时间展示参考日期/时区；修正“不是周五，是周六”使用最新肯定内容并展示字段变化。生成的标题、依赖、估时与假设可局部编辑；局部编辑产生新候选并重校验，不把原批准沿用。

## 8. 八条可回放的核心闭环

每条均需用固定演示输入、初始数据、预期差异、预期终态与异常分支记录。设计原型使用明确标注的模拟数据；实际能力验收之后再由真实 KernelClient 替换，不能把模拟回执称为持久化成功。

### F01 首次进入到第一项事务

Harness 加载插件 → S01 核对人工 UI 身份、Core 位置并选择/建立 workspace → S27 严格策略 → S26 可先跳过 AI → S04 输入 → 预览/手工 → S16/L07 可信人工批准 → Host RPC/Core → S20 → S02/S10 唯一新任务。宿主会话不是 Core workspace；无模型仍可手工；未批准无任务，退出留草稿。

### F02 零碎材料到有依据的多个任务

S03/L01 收集多行材料和来源 → S04 编辑并预览 → S17 澄清截止强度/动作对象 → S16 查看新任务、关联与未知字段 → 局部修改后重校验 → 批准并 S20 提交 → S03 原文标 processed 且保留转化引用 → S09/S10 查看结果。无权限附件不进入上下文；取消/失败保留原文，重复提交不重复建任务。

### F03 模糊目标到项目和可执行计划

S05 → S06 明确成功标准、可用时间及硬边界 → AI 生成拆解到 S16 → S08 审阅里程碑/依赖并检查父子不重复估时 → S13 计算时间分配 → S18 处理容量缺口 → S16 比较可行方案 → S20 应用 → S02 开始下一步。无解分支仍可记录目标/任务，但不称计划可行；依赖环拒绝且旧结构不变。

### F04 日程变化到稳定局部重排

S13 收到新 busy/手工预约 → S14 检查来源、锁定与受影响范围 → S16 候选局部调整 → S18 显示未排入和硬约束 → 另一客户端修改使提案进入 S19 → 基于最新数据重算并重新批准 → S20 → S13 显示新计划。验收：旧批准失效，已开始/过去/锁定项不移动，无关备注不重排全周；外部日历陈旧时有新鲜度提示。

### F05 从下一步执行到反馈与再次安排

S02/S10 → S21 开始 → 暂停/收起面板/宿主关闭/插件热重载 → 重开查 Core 记录 → L08 核对投入、剩余量或阻塞 → 独立完成任务 → S22 → S16 调整 → S20 → S02。25 分钟不自动完成 90 分钟任务，UI 重挂载不重复记时；Core 一并停止时按中断处理，不宣称 Harness 网页提供原生后台。

### F06 重复事务与习惯的一次例外

S23/S24 建立/查看规则 → L06 明确本次、以后或全系列 → 对某次改期/跳过 → S16 比较受影响实例 → S20 应用 → S13/S24 核对唯一发生键 → S23 记录活动 → S22 查看周期反馈。P0 演示基础循环/单次例外，P1 再演示周配额和完成后间隔。验收：改期不生成重复实例，跳过不算完成，一次完成不结束系列，历史不被规则编辑抹除。

### F07 周回顾到可撤销的偏好与下周计划

S22 选周期 → 汇总实际记录、用户报告与标注推断 → 用户修正证据 → 提议减量/拆分/改估时/更新偏好 → S16 展示规则和计划各自影响 → 必要时 S27 检查敏感上下文 → L07 批准 → S20 → S13/S02 看到下周期结果。模型失败仍可手工回顾；一次行为不自动变成永久规则；拒绝偏好更新不会删除回顾事实。

### F08 外部 agent 协作到撤权和可审计结果

S29 验证真实 integration/宿主 agent principal → 分开人工 UI 与工具输出，展示日志保留/后续模型重用风险 → 最小 grant → Core/bridge 裁剪允许结果，device_only 不因当前本地模型外发 → agent typed proposal → S15/S16 → 独立人工批准或有效预授权 → S20/S30 → L13 撤权 → 再读/提交/恢复拒绝。批准凭据不回 agent，宿主回放不重复 execute；无需内置模型重解明确结构化动作。

辅助流程同样须设计：S11→S12 保存/复用查询，S25 的提醒权限拒绝/测试送达，S26 下载中断/角色切换，S28 只读预检→隔离→导入→核对/回滚，S30 查询未知回执/恢复 interrupted Run。它们不额外充作上述八条核心闭环数量。

## 9. 隐私、权限与错误映射

日常页用易懂文案，授权页显示字段、目的地、有效期、effects 和日志去向。人工 UI face 使用可信用户上下文；agent tool face 使用独立 integration grant，禁止继承人工 session token 或仅凭当前模型身份放行。返回工具的对象 ID、标题、摘要与正文都先过导出策略，必要时只返回安全回执/拒绝；“人工界面可查看”不是隐私旁路。关闭 Core 云路由不等于撤销 agent 读取授权，历史工具结果可能已进会话并被后续模型使用，无法假称收回。

| 契约错误/状态 | UI 恢复 |
| --- | --- |
| VALIDATION_FAILED | 定位字段/关系/时间错误，保留输入；无副作用 |
| REVISION_CONFLICT | S19 显示依据已变化，拉最新数据并重提案，不静默覆盖 |
| POLICY_CHANGED | S27/S16 重新校验数据流和影响，旧批准不能复用 |
| PERMISSION_DENIED / 会话过期 | 清除不再允许的内容，重新认证或进入适当授权；不把模型自报身份当权限 |
| APPROVAL_REQUIRED / EXPIRED | S16/L07 审阅当前内容重新批准，不能只重放过期按钮 |
| IDEMPOTENCY_MISMATCH | 保留原操作回执并提示内容已变；新修正用新操作，不自动绕过去重 |
| RESOURCE_EXHAUSTED / PROVIDER_UNAVAILABLE | 显示预算/模型限制，按许可换模型或手工继续；local_only 不切云 |
| RUN_NOT_FOUND / 事件游标失效 | 查询最新快照，解释不可恢复的 Run；对象事实不随日志缺口丢失 |
| effects needs_reconciliation | 本地提交保持，展示待核对与安全检查入口，不能直接“一键再发” |

原始诊断与内容导出必须主动启用、限时和可清除，默认只保留 ID、阶段、耗时、状态、路由及版本摘要。设计图、演示浏览器和原型不接入真实个人数据、模型密钥或生产 agent；敏感数据与权限页仍用完整真实语义的模拟样例。

## 11. 设计交付的完成标准

1. 30 个屏幕族与 16 个弹层均有明确设计；主导航、详情返回、深链和辅助路径没有死路。对每个“更多/管理/查看详情”说明实际目标，不以未设计抽屉掩盖缺页。
2. 八条核心流程能从固定起点回放到明确终态，每条至少含一条异常/退出分支；逐项差异、澄清、冲突、stale、批准、回执和外部失败均能被实际打开检查。
3. 首期视觉需覆盖 Harness 工作台/窄停靠/详情/批准容器，验证宿主主题、焦点、分栏、快捷键及卸载。清晰日程完整 30 屏按表验收，旧七图不算插件新视觉；后续 Flutter 桌面/平板/手机另设证据，不减少功能目标。
4. 所有虚构数据、模拟 AI/提交/通知和不可用能力标清。设计或 React 演示通过只证明表达/导航，不代表 Rust Core、真实隐私、宿主工具隔离、平台后台或发布能力已验证。
5. 最终交付附屏幕/状态/流程索引和证据位置，按“已设计、已绘制、可演示、接真实内核、产品验证”分层记录。缺页、缺异常分支、仅有描述未有必要视觉/流转证据时，不能宣称完整 UI 设计交付完成。

## 12. 展示与业务实现的分界

首期链路为 React presentation → 注入的 Client service/model → Harness 生成 Host Remote/RPC → Zodo bridge → Rust Core 应用入口。React 只管理草稿、焦点/IME、局部导航和查询投影；Host bridge 注入可信身份、限制输出与协议适配，Cordis 管生命周期。领域规则、权限、版本、幂等、时间、依赖、排程、提交及持久事实留在独立 Core；UI/Cordis 不直写 SQLite，也不把 Harness 会话日志当 Zodo 事实库。[官方 Web Client 分层](https://deepseek-harness.github.io/deepseek-harness/reference/subsystems/web-client)

插件卸载释放 UI effect/订阅，Core 已持久化对象不随组件销毁。重连按 Core 自有 baseline/cursor/receipt 恢复，不能假设宿主普通通知可靠回放；宿主会话/Conversation replay 不调用变更命令。Core 停止后的 Run 分类恢复由其自身负责；宿主网页不保证系统后台、移动通知或模型持续运行。人工批准 UI 与 agent 工具面独立，宿主批准仅是门控之一，最终 Core 仍校验绑定内容与当前策略。

后续 Flutter/Riverpod 只管理独立客户端视图，复用 Core command/query/event，不能把其规则套到首期 React 上。演示保持相同生命周期/错误形状，保留 S/L/F 编号逐项替换证据；本包没有产品代码，也未修改七张 PNG 或旧项目。

## 0. 首期载体、两种权限面与日志边界

首期为 Harness 内 React + Slots 的 Zodo 工作台、详情及批准视图，Host RPC bridge 调用 Core。五业务入口在插件内部组织，设置为 Zodo 局部设置，不改宿主全局导航、主题、会话模型或审批策略。下文“页面/抽屉”均映射到宿主支持的容器；标明手机/原生的行为仅属于后续 Flutter，不代表 Harness 网页可访问原生后台、系统通知或本地数据库。

人工 UI face 与 agent tool face 分开认证/授权/输出裁剪。人工看到完整详情，不意味着应把同样正文、摘要或标题返回给模型；工具结果可能进入 Harness 会话日志，之后换模型、导出或回放时仍可被使用。device_only 不能仅因当前 agent 是本地模型就外发到会话；若不能约束完整接收/保留路径，返回安全拒绝或经策略允许的最小回执，不能先传正文再警告。需要私密材料的本地理解可由受限 Core gateway 完成，不自动复制到宿主 prompt。

下文批准均指具体 Core 变更的有效批准。Host 的工具允许一次只是一道门控，不等价于 Core grant；可信人工回调绑定主体、提案 hash、数据/策略版本和影响。批准凭据不交给 agent。React/Cordis 不存第二份权威事实，不用宿主历史事件重建后自动执行保存；关闭/热重载后的恢复见第 11 节。

## 4. 设置主页面与模型连接

### SET01 设置首页（主要页面）

Zodo 局部设置分类保持“时间与提醒 / 模型与处理方式 / 数据与隐私 / 外部助理 / 数据与备份 / 显示与辅助功能”。摘要显示 Core/Host 位置、外部连接和最近备份；宿主拥有的主题/快捷键只给正式设置入口，不在插件复制。未配置写“尚未连接/尚无备份”。

### SET02 模型与处理方式（主要页面；D06 的代表画面之一）

上方标题、当前处理方式摘要；中部左右对比或窄屏上下排列：

- **此设备**：准备状态、实际可用能力、上次测试结果；动作“测试运行”“更换模型”“移除文件”。
- **云端连接**：连接名“我的云端连接”、服务提供方、状态、允许的数据范围；动作“管理连接”“测试连接”。
- **使用规则**：默认“只在此设备处理”；另可选“特定内容允许云端，其他内容留在此设备”。规则须显示具体范围，不能只写“自动选择最佳模型”。

“添加 Core 连接”在详情输入名称、服务类型、必要地址/凭据/模型与测试；密钥遮掩、错误不回显，由安全存储持有。保存不等于发送资料，测试只发无个人内容请求。Harness 当前 agent 的模型/凭据由宿主管理，插件不复制秘密、不偷偷改全局 provider；显示实际路由与可用性，测试成功也不授予正文导出。

保存后摘要：“已保存连接。尚未允许发送个人事项。”更换服务或可读范围时重新检查已有待审建议；不把前一家服务的同意复用给新服务。

### SET03 模型移除与不可用

“移除本地模型文件”用短确认弹层，列出模型名称与占用空间，主按钮“移除文件”。说明“任务和日程会保留，仍可手动管理”。云端连接删除弹层显示“删除连接后，需要重新填写凭据才能使用”，不影响已经保存的任务。

行内不可用文案：“此设备暂时无法生成建议。输入内容已保留。”动作“重新测试”“手动编辑”；只有已有云连接且用户主动选择时才出现“改用云端”，并先展示本次数据流向。

## 5. 数据与隐私：规则与本次发送分开

### PRIV01 数据与隐私（主要页面）

顶部显示真实 Core/Host/浏览器位置，仅同设备时写“个人事项保存在此设备”。说明“Core 本地处理不自动转云；交给宿主 agent 的结果另受日志/后续模型策略约束”。页面分三组，分别标人工查看和 agent 可读范围，不以一组勾选混授权：

- **处理范围**：任务标题与时间、目标与成功标准、笔记正文、附件；每项有“此设备 / 可按次发送 / 明确允许的服务”范围。
- **外部读取**：已授权的助理与范围，进入详情可暂停或撤销。
- **活动与诊断**：查看数据访问、关闭诊断原文、删除诊断内容；默认不保存个人正文到诊断记录。

私人笔记标记不是装饰；含 N01 的请求若不满足策略，界面指出“有 1 份私人笔记未包含”，不能先发送再提醒。用户移除正文后可以继续使用其他允许字段。

### PRIV02 本次数据流向（详情抽屉；必须可从生成入口打开）

标题“这次将发送什么”，第一屏展示：

| 区块 | 连贯示例 |
| --- | --- |
| 用途 | “改写作品集案例说明” |
| 接收方 | Core 选定 provider，或 Harness 会话/工具日志及当前 agent 路由；显示实际地址/保留边界，后续换模型可能重用历史 |
| 将发送 | G01 标题、成功标准；N02 本次粘贴的案例草稿；必要的语言要求 |
| 不包含 | N01 私人笔记、其他目标、日历详情、凭据 |
| 选择 | 默认“仅这一次”；“以后对同类内容也允许”需单独选择并展开具体规则 |
| 主动作 | “发送这些内容”；次动作“返回修改”“取消” |

内容清单可逐项展开实际文本或附件名称；不只展示“3 条数据”。删除某项后若建议能力受影响，写“缺少案例草稿，只能提供通用写作建议”，让用户选择。发送前改用不同服务、添加笔记或更改范围时，旧同意失效，重新展示摘要。

“发送这些内容”只授予明确的一次导出，不批准计划变更；未点击不发送。走受限 Core 本地预览时无需重复打断已有授权；走 Harness agent 时，即使当前本地模型也需说明工具历史保留/换模型风险，device_only 不因此放行。无法保证后续目的地时不传该材料，可仅在人工详情查看，不能用“仅一次”承诺已入日志正文以后不被重用。

云端流式生成过程中无法保证撤回已经发送的内容。点击“停止生成”后写“已停止后续生成；已发送的内容无法从此处撤回”，不显示“已撤回所有数据”。

## 6. 外部助理：连接、限权、暂停和撤销

### AG01 外部助理（主要页面；D06 代表画面）

空态：“还没有外部助理连接”；主动作“添加助理”，说明“你可以限定它能看什么、能做什么”。非空列表每行显示名称、连接状态、可访问范围、最近访问时间，避免只显示一个“已连接”图标。

A01 行示例：“桌面助理 / 已授权 / 仅作品集第二版 / 可读取、可提出建议 / 不可直接修改”。最近活动“09:32 读取了 5 项任务”。列表提供“查看授权”，暂停和撤销在详情中，防止误触。

### AG02 连接授权（宿主完整详情；手机整页仅为后续 Flutter）

标题“允许桌面助理访问哪些内容？”，依次展示：

1. **是谁**：连接名称、来源应用/地址；未验证来源写“来源尚未验证”，不能由对话里一句“我是可信助理”消除。
2. **范围**：仅 G01/P01；其它工作空间、收集箱与私人笔记默认不选。
3. **可读取**：五项任务标题、估时、状态、允许的空闲时间；可看实际示例。默认不给笔记正文、附件或全部日历标题。
4. **可操作**：默认“提出建议”；“创建少量任务”“调整日程”“删除事项”“向外部发送”分别授权，不用“完全访问”总开关吞并差异。
5. **有效时间**：本次演示选择“今天结束前”。支持具体截止与随时撤销，不能把关闭弹窗解释为批准。

说明：“结果可能写入 Harness 会话日志，并在后续换模型或继续对话时再次使用。”紧邻读取范围展示；当前模型本地不能覆盖这一风险，device_only 正文/标题/摘要仍按导出策略拒绝。人工 UI 可看与 agent 可读是两张授权面，人工 token 不透传给工具。

底部摘要“可读取作品集的 5 项任务、可提出建议；修改仍需你确认”。主按钮“允许这些访问”；次按钮“拒绝”。无勾选范围或身份验证未完成时，按钮不可激活并有具体原因。

### AG03 连接详情（主要页面或深链接详情路由）

上半部展示当前权限与有效期；下半部为“访问记录 / 提出的建议”。权限修改后保存为明确的新授权。缩小范围立即影响新读取及尚未执行的动作；不声称已读出的内容自动删除。

“暂停访问”短弹层说明“暂停后，这个助理不能继续读取或提交新内容。你可以稍后恢复。”主按钮“暂停访问”。恢复需核对当前范围；不自动续期已过期授权。

“撤销授权”短弹层列出 A01、其读取范围及尚未处理的提案数。文案：“停止后续访问。它之前读到的内容无法从这里收回。”主按钮“撤销授权”，次按钮“保留授权”。

撤销后列表显示“已撤销 · 09:39”；等待执行的操作停止并在记录里说明。若授权撤销发生在提交完成后，展示已提交事实与“查看修改”；不能伪装成已撤回。已保存、仅供本人查看的建议可保留，标注“来源授权已撤销”；若本人希望使用，动作是“复制为我的草稿”，重新检查范围与影响，不能直接沿用旧批准。

### AG04 活动记录（主要页面 + 单条详情抽屉）

时间线支持“读取 / 建议 / 已保存 / 未完成”筛选。记录写“桌面助理读取了作品集的 5 项任务”“提出了 2 处时间调整”“你应用了计划”，不把 agent 的提议写成用户完成事实。详情列实际范围、结果和去向，默认不展示敏感正文。

## 7. AI 澄清、预览和提交的连续主流程

### AI01 入口与生成（嵌入主页面）

G01 指令输入：“把这些工作排到月底，尽量放在上午，每天不超过一小时。会议保持不动。”输入旁的处理位置是可点击摘要，不是只读盾牌图标。主动作“预览安排”，输入始终可编辑。

阶段反馈使用实际状态：“正在整理你的要求”“正在检查可用时间”。显示“停止生成”，不使用虚构进度百分比。用户离开后，在“活动”查看长任务；重新打开不会丢草稿。

### AI02 需要澄清（详情抽屉顶部，保留来源目标）

标题“还需要确认一件事”，问题“周末也可以为作品集安排时间吗？”；选项：

- “只安排工作日”。
- “本周六可以，周日不安排”。
- “周六和周日都可以”。
- 文本入口“补充其他要求”。

演示选择第二项，成为本次安排条件；另有未勾选的“保存为以后默认”。不把一次回答升级为永久偏好。底部“继续预览”“先保存草稿”。用户没有回答时可保留未排入事项，不能推断为同意周末工作。

### AI03 计划预览（完整抽屉；D04 / M01）

顶部“作品集 · 计划预览”，紧邻状态“尚未应用”。摘要“安排 5 段，共 4 小时；两场项目沟通保持原位”。时间范围“10 月 24 日—10 月 31 日，上海时间”。显示五段 S01–S05；点击每行可看目标、估时来源、依赖与允许时段。

分区顺序：

1. **本次变化**：新增五段分配；若只是排入已有任务，不写“新增 5 个任务”。
2. **保持的安排**：C01、C02 与锁定事项。
3. **未排入**：完整方案写“无”；局部方案列剩余分钟与原因，不能隐藏。
4. **本次条件**：每天最多 1 小时、尽量上午、本周六允许、周日不安排。
5. **还可以调整**：时间行“更改时间”，每项“这次不安排”；不要求拖拽。

底部固定主按钮“应用这份安排”；次按钮“继续调整”；文本动作“放弃预览”。“应用”始终在看得见的差异之后，不放在初次生成状态。

Harness 窄容器使用逐项议程与可展开差异，不缩小周网格；长清单主动作不遮末行，读屏明确原/新时间。旧 M01 仅作后续 Flutter 手机/窄屏参考，其图上是单项邮件改期，并非此处完整五段方案的截图；首期插件新布局仍待绘制。

### AI04 不可行与局部方案（预览内状态）

在另一个演示分支，用户明确取消每日 1 小时上限，改为“只使用今天 14:00–15:30 这段时间完成 4 小时”。B01 的 90 分钟不可容纳全部工作，标题“有 2 小时 30 分钟暂时放不下”；保留原估时，不缩减为 90 分钟。选项“允许其他日期”“减少本次范围”“只保存任务”。如果选择局部安排，主按钮写“应用这 90 分钟”，明确未排入部分，不能仍写“完成全部安排”。

固定会议冲突时显示“与 10:00–11:00 的项目沟通重叠”，提供“保持会议，重新安排”“手动选择时间”。不以高优先级或模型确定程度覆盖锁定。

### AI05 预览过期（预览内行内条）

09:28 同一 Core 的另一已授权客户端把 10/26 10:00–10:45 标不可用，不暗示已实现多设备同步。旧预览显示“安排依据已变化，需要重新检查”，应用停用、候选可读；动作“重新检查/返回调整”。

新建议将 T02 改为 10/26 11:00–11:45，其余四段不动。只显示新增的这处变化，并说明“10:00 的时间已不可用”。需要用户重新点“应用这份安排”，不会沿用旧按钮点击或之前同意。若时区、日期解释、模型处理规则变化，同样重新检查对应部分。

### AI06 保存中、成功与结果不明

正常路径：可信人工面点击应用 → Host RPC bridge 注入人工上下文并绑定 Core 批准 → Core 重验版本/授权提交 → 持久回执后“安排已保存”。宿主工具审批不自动变成这次批准，批准凭据不进 agent 结果。摘要“5 段已加入日程”，任务仍未完成；提醒/effects 独立。

如果网络在提交之后断开，显示“正在确认是否已保存”，先查结果，不能让用户反复创建计划。已保存则显示原结果；确知未保存后才提供“重试保存”。未知状态不写“保存失败，请再次提交”。

“撤销这次安排”创建新的变更预览：说明删除哪些分配、已开始或后来修改的哪些项目需要保留。不能撤销已发生的工作事实或假称收回外部已发送通知。

计划保存但提醒设置失败时，显示“安排已保存，提醒尚未设置”，动作“处理提醒”。不回滚已存计划，也不把整项标作失败。

### AI07 失败、停止与输入保留

| 失败类别 | 主文案 | 动作与边界 |
| --- | --- | --- |
| 模型不可用 | “暂时无法生成建议，输入内容已保留” | 重试 / 手动安排；云端仅在明确选择后打开数据流向 |
| 缺信息 | “还不知道‘下周找一天’指哪一天” | 给出选择或保留未知；不红色归咎用户 |
| 权限不足 | “当前授权不允许修改这些事项” | 查看范围 / 仅保存建议；不自动扩大范围 |
| 处理规则变化 | “处理方式已更新，请重新检查这份建议” | 重新检查 / 返回修改；已撤销的云端同意不可复用 |
| 已知保存失败 | “尚未保存，原来的日程没有改变” | 重试保存 / 返回调整；仅用于确认未提交的失败 |
| Web 离线 | “当前离线，草稿只保存在这个浏览器” | 继续编辑 / 联网后检查；不能显示“已加入日程” |
| Harness 断网但 Core 可达 | “云端暂不可用，可用本地功能保留” | 按实际 Core 能力手工/本地处理，不把浏览器断开 Core 当已提交 |
| 后续 Flutter 原生离线 | 另行验证本地管理与模型能力 | 不由 Harness 网页或 Electron 外壳直接兑现后台/提醒/离线库 |

“停止生成”后，预览生成路径显示“已停止，输入仍在”；若收集箱原文早已保存，则写“收集内容已保留”。不能把停止解读为删除已有事实。提交已经完成时显示真实结果，停止按钮不承诺回滚。

## 8. 数据与备份：导入、导出、恢复

### DATA01 数据与备份（主要页面）

主区三个明确入口“导入事项”“导出数据”“从备份恢复”，下方显示最近成功备份和文件位置（仅可访问时）。未创建备份写“尚未备份”；不能显示编造的定时状态。导入是增加或合并选择的内容，恢复是替换当前业务快照，两者不共用模糊的“打开文件”。

本规格设计 Zodo 备份、CSV 任务和日历占用快照的流程；具体格式只有实现与验证后开放，尚未支持的格式明确写“暂不支持此格式”。不在原型中伪造文件解析成功。

### DATA02 导入向导（三步主要页面）

1. **选择内容**：选择文件、显示文件名与来源；说明“先检查，不会立即修改”。不直接打开旧项目正在使用的数据库。
2. **检查映射与问题**：展示标题、日期、估时、项目、来源；缺失值保持未知。歧义日期要确认，缺标题要补全，重复显示匹配依据。私有笔记不会因导入自动允许云端读取。
3. **确认导入范围**：计数、去向、重复处理和未导入问题；主按钮明确数量，成功后可查看结果与未导入项。

统一演示文件“作品集_补充任务.csv”有三行：

| 原行 | 内容 | 检查结果 |
| --- | --- | --- |
| 1 | 筛选 3 个项目素材，45 分钟 | 与 T01 有相同来源标识，跳过重复 |
| 2 | 整理参考链接，15 分钟 | 可新增至收集箱，不自动加入 G01 的 4 小时计划 |
| 3 | 标题为空，备注“准备介绍稿” | 需补全；备注不能自动变成确定标题 |

摘要“1 条可新增 · 1 条重复 · 1 条需补全”。用户可修正第三行或选择“只导入这 1 条”。排除项明确列出，不能将无效记录静默丢弃。成功文案“已导入 1 条；1 条重复已跳过，1 条未导入”，提供“查看新增事项”“导出问题清单”。选定的有效集合一次保存，失败不出现半批写入。

重新导入同一文件时，已经导入的第二行也被识别为重复；不再次创建。导入错误保留映射和修正结果，给出可重试范围。

### DATA03 导出选项（详情抽屉）

标题“导出哪些内容？”，范围为整个工作空间或所选目标，格式按支持情况提供。清单显示是否含笔记正文、附件和历史记录；默认不包含密钥、有效授权或诊断原文。提示实际风险“导出文件可被拿到文件的人读取”，不虚构端到端加密标志。

底部“创建导出文件”，Core/Host 生成及实际下载/保存完成前不写“已备份”。展示名称、大小和受支持下载/保存动作；不让浏览器任意写 Host 文件路径。后续 Flutter 手机再接系统分享。取消只显示“已生成、尚未保存”，不更新最近备份时间；文件正文不作为 agent 工具结果自动返回。

### DATA04 从备份恢复（三步主要页面 + 最终短确认）

检查页显示备份时间“2026-10-24 09:10，上海时间”、来源设备、数据数量和兼容性；当前时间演示为 09:40。不兼容、损坏或缺少必要部分时停止恢复，保留当前数据并可查看问题。

对比页写“将使用 09:10 的事项替换当前事项”，分列目标、任务、日程、执行记录的变化；演示对比为“移除刚加入的 5 段日程，保留备份中的 5 项任务”。若 CSV 导入分支也已执行，另显示“移除导入的参考链接”。不能凭文件日期暗示恢复一定完整。

恢复不恢复 provider 密钥或外部助理有效授权；连接与隐私保护按当前设备重新检查。展示“外部助理需要重新授权”，避免旧备份使撤销的访问复活。

最终确认：“恢复前会先保存当前快照。恢复后可以返回这次操作前的状态。”只有安全快照实际完成后，才激活“恢复这份备份”。无需为每次恢复让用户抄写长句；清楚列影响、用明确按钮和可回退机制。主按钮“恢复这份备份”，次按钮“返回检查”。

恢复中页面显示阶段并避免编辑被替换的工作空间；成功后“已恢复到 09:10 的备份”，动作“查看事项”“查看恢复前快照”。失败则“恢复未完成，当前事项仍保留”，提供重试或问题详情；结果未知先核对，不同时展示新旧混合列表。

## 10. 设计验收清单

- 页面、抽屉、弹层有唯一入口和返回位置；关闭后回到触发控件，草稿不丢。
- 每个主按钮都能回答“对哪些内容做什么”；不可点击时有文字原因。
- 加载、空、失败、过期、离线和结果未知均有对应状态，不靠一个通用报错覆盖。
- 预览与提交、保存与提醒、安排与完成、暂停与撤权、导入与恢复分别表达。
- 键盘可完成范围选择和时间编辑；读屏可读差异，200% 文字缩放不遮挡底部主按钮；状态不只依赖颜色。
- 本地模型未准备、云连接已保存但未授权、agent 只读、撤权后待审、保存中断与恢复失败都必须可演示。
- 七张旧图只是选定方向参考；Harness 演示与个人空间分开，模拟成功不证明 RPC、Core、权限或恢复已实现；Flutter 后续另验。

## 11. 宿主重载、回放与持久恢复的验收

关闭 Zodo tab、切会话、卸载/热重载插件时释放 Slots、订阅和 UI effect；已持久化 Core 事实、Proposal、Run、receipt、outbox 不删除。未提交草稿仅在明确的安全草稿存储保存，不能写进共享会话日志当备份。Core 保持运行才可能继续工作，Core/Host 一并停止时不承诺推理不断。

重挂载先核对人工身份、workspace、policy_revision，再取 Core 快照、cursor 和原操作回执。状态未知先查 receipt，不由 React effect、RPC 自动重连或宿主历史回放再次执行写命令；需要重试时沿用原幂等键，内容修改产生新提案/批准。未知外部送达先对账，不随重连再发通知。

宿主会话/Conversation 回放可呈现安全摘要与已有对象链接，但只做读取。人工详情可读的私密字段不自动进工具结果/审计导出；模型切换、grant 撤销、会话续接都重新检查 agent 结果导出。至少验证关闭后重开、热重载、同对象双客户端修改、撤权后恢复、提交后断线及模型切换六种场景；这些均未实施通过。

## 宿主框架与局部样式

首期使用 React，通过宿主 Slots 提供 Zodo 工作台、详情和批准视图，经 Host RPC 桥接 Rust Core。Harness 保有全局导航、会话、右侧停靠布局、主题、快捷键、Esc/模态和插件生命周期的所有权。五个业务入口“今天/收集箱/目标/日程/回顾”仅在 Zodo 自有内容区组织，可为内部分段或局部导航，不要求替换宿主 sidebar 或 root。

组件继承可用的宿主字体、主题、焦点、控件与模态约定；清晰日程的青绿强调仅作用于 Zodo 局部并服从对比度。样式以插件根节点作用域限定，不全局 reset、不覆盖宿主 CSS、不注册第二棵 React root；不得为私有组件导入其他功能插件实现。tokens 见 [design-tokens.json](prototype/design-tokens.json)，具体宿主局部样式约束以更新后的 tokens 和技术验证为准。

Slots 提供类型化组合与生命周期注册；具体扩展位、props、可用容器需在锁定 Harness 版本后验证，不把本文的概念组件名当已存在的宿主 API。[官方 Slots](https://deepseek-harness.github.io/deepseek-harness/reference/subsystems/slots)

## 容器适配与信息层级

按插件实际可用面宽适配，而非浏览器外窗宽：宽停靠面可显示主区与详情/提案双栏；受限侧栏优先摘要、下一步和“打开详情”；窄容器用单栏和可返回详情。既有三栏 PNG 可参考内容分组，不能照搬其左侧全局栏。200% 文字、宿主分栏/浮出/收起、长正文和 IME 键盘下主动作仍可达。

## 组件契约

- ZodoWorkbench：插件内五入口、局部搜索/收集、Core workspace 和连接状态；保留筛选/滚动，不修改宿主全局导航。
- IntentComposer：输入始终可编辑、IME、防抖、最新请求、生成/取消、实际处理位置与手工替代；预览不写正式事实，也不默认送入宿主 agent 会话。
- TaskRow/Detail：完成、计划、阻塞、剩余量分开；React 只持有投影和草稿，Core 校验关系/时间/提交。
- ProposalDiff/Approval：逐项差异、来源、假设、影响、stale/冲突与确认；人工批准经独立可信 UI face，绑定当前内容，不把 agent 工具结果或宿主工具允许一次当 Core 批准。
- Agenda/Timeline：预约、容量、分配与建议有文字/形状区别，锁定和未排入信息不因容器变窄丢失。
- ExecutionRecord/Review：投入、剩余量、任务完成和目标证据分别记录；宿主关闭后重开查询 Core，不凭组件计时补写执行事实。
- ModelPrivacy/Grant：分开 Core 模型配置、宿主 agent 实际路由、人工可读范围和模型可读范围；device_only 禁止因当前模型本地而直接返回到 agent 会话。
- Receipt/Recovery：本地 committed 与外部 effects 分开展示；热重载/重连先查 receipt/cursor，历史回放纯渲染，不重新 execute。

正常、空、加载、编辑、失败、断线、无权、长内容、过期/冲突/取消的适用组合以逐屏表为准。中文字形、可见焦点、触控目标、读屏、缩放与减少动效先在 Harness 插件验证；后续 Flutter 另验，不能彼此代替。

## 首期必须补齐的技术和 UI 证据

1. 锁定 Harness 版本，验证插件装载/卸载、可用 Slots、宿主详情/批准载体、内部五入口、局部样式与快捷键冲突处理，不夺取 root/全局导航。
2. React → Client model/注入 service → Host RPC bridge → Rust Core 的真实纵切；Cordis 只管生命周期和接线，Core 保有事实、授权、时间、依赖和提交。
3. 人工 UI face 与 agent tool face 独立授权、输出裁剪和批准。工具结果可能写会话日志并在后续换模型时重用；device_only 不能仅因当前本地路由而导出到 agent 历史。
4. 中文 IME、持续编辑、取消、stale、冲突、未知提交、receipt 与 effects 全状态；宿主关闭/插件热重载后按 Core 回执和快照恢复，宿主事件回放不重写业务。
5. 宿主/网络/Core 分别掉线、授权撤销、model 改路由、会话切换、插件多实例及 Core 重启的实证。UI 关闭不删除 Core 持久事实；Core 也停止时不承诺推理/通知持续执行。
